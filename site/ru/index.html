Читайте строки по первичному ключу через аутентифицированный RESP MGET. Записи PostgreSQL автоматически инвалидируют затронутые элементы кэша.

Аутентифицированный RESP API · PostgreSQL 14–18 · Открытый исходный код

В версии 3.1.0 ёмкость арены измеряется в байтах, что при подходящем бюджете позволяет хранить миллионы небольших ключей. Добавлены секционные блокировки, попадания по одному ключу без аллокаций, дешёвый учёт записей и отложенные промахи при блокировках отношений. Руководство по обновлению.

Один вызов. Два пути чтения.

Подходящее попадание возвращает сохранённую строку. Промах или обход кэша читает исходную таблицу. Ваши обычные запросы SELECT сохраняют существующий путь.

RESP2 │ чтение по первичному ключу
-- Attach your table once.
SELECT local_cache.attach_table('public.items');

-- Read rows by primary key.
MGET CRUD:pglc_demo.public.items:{"id":42} CRUD:pglc_demo.public.items:{"id":7}

Это ваш тип нагрузки?

Выбираете кэш? Сравните страницы PostgreSQL, строки, материализованные представления и Redis.

Стоит измерить

  • Повторяющиеся полные чтения по первичному ключу.
  • Небольшой горячий набор целых строк.
  • READ COMMITTED на одном доступном для записи основном сервере.
  • Приложение, способное использовать аутентифицированный RESP MGET.

Оставьте обычный SQL

  • Соединения, диапазоны, агрегаты или произвольные результаты запросов.
  • RLS, секционированные или унаследованные таблицы.
  • База данных, в которую нельзя установить нативное расширение.
  • Нагрузки без измеренной выгоды.

Перед началом

Заменяет ли это shared_buffers?

Нет. PostgreSQL кэширует страницы базы данных. Это расширение отдельно кэширует сериализованные целые строки по первичному ключу. См. сравнение путей чтения.

Кэширует ли оно обычные запросы SELECT?

Нет. Общий кэш строк использует только аутентифицированный RESP MGET. Существующие запросы сохраняют обычный путь выполнения PostgreSQL.

Заменяет ли это Redis?

Нет. Конечная точка RESP2 ограничена. Здесь нет универсального набора команд Redis, TTL, pub/sub или распределённой координации. Сравните пути cache-aside для PostgreSQL и Redis.

Как проверить обновления и откат?

Руководство по инвалидации описывает работу триггеров. Руководство по обновлению описывает переход с 3.0.0 на 3.1.0, а также прежнюю миграцию с 2.x.
