在 PostgreSQL
内部缓存行数据。

通过 SQL mget 或 RESP 按主键读取行。PostgreSQL 写入会自动使受影响的缓存项失效。

本地试用 → 与 SQL 比较 →

显式 SQL API · PostgreSQL 14–18 · 开源

一次调用，两条读取路径。

符合条件的命中返回已存行。未命中或绕过缓存时读取源表。普通 SELECT 查询保留现有路径。

psql │ 主键读取
-- 只需关联一次表。
SELECT local_cache.attach_table('public.items');

-- 按主键读取行。
SELECT local_cache.mget(
  'public.items', ARRAY[42, 7]::bigint[]
);

值得测量的场景

  • 反复使用完整主键查找。
  • 由完整行组成的小型热数据集。
  • 单个可写主库上的 READ COMMITTED。
  • 能够调用显式 SQL API 的应用。

保留普通 SQL 的场景

  • 连接、范围查询、聚合或任意查询结果。
  • RLS、分区表或继承表。
  • 无法安装原生扩展的数据库。
  • 没有测得收益的工作负载。

试用前须知

这会替代 shared_buffers 吗？

不会。PostgreSQL 缓存数据库页，此扩展则单独按主键缓存序列化整行。参阅读取路径比较.

它会缓存普通 SELECT 查询吗？

不会。只有显式 local_cache.mget 调用使用 SQL 缓存。已有查询保留 PostgreSQL 的正常执行路径。

它能替代 Redis 吗？

不能。可选 RESP2 接口功能有限，不提供通用 Redis 命令集、TTL、发布订阅或分布式协调。请比较PostgreSQL 与 Redis cache-aside 路径.

如何检查更新与回滚？

失效指南提供双会话测试。可运行示例检查未提交写入、读取自身写入、回滚和已提交更新。
