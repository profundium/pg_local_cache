值得测量的场景

  • 反复使用完整主键查找。
  • 由完整行组成的小型热数据集。
  • 单个可写主库上的 READ COMMITTED。
  • 能够使用经过身份验证的 RESP MGET 的应用。

保留普通 SQL 的场景

  • 连接、范围查询、聚合或任意查询结果。
  • RLS、分区表或继承表。
  • 无法安装原生扩展的数据库。
  • 没有测得收益的工作负载。

试用前须知

这会替代 shared_buffers 吗？

不会。PostgreSQL 缓存数据库页，此扩展则单独按主键缓存序列化整行。参阅读取路径比较.

它会缓存普通 SELECT 查询吗？

不会。只有经过身份验证的 RESP MGET 会使用共享行缓存。现有查询仍按 PostgreSQL 的正常路径执行。

它能替代 Redis 吗？

不能。RESP2 接口功能有限，不提供通用 Redis 命令集、TTL、发布订阅或分布式协调。请比较PostgreSQL 与 Redis cache-aside 路径.

如何检查更新与回滚？

失效指南介绍写入时的行为。升级指南说明从 3.0.0 升级到 3.1.0，以及此前从 2.x 升级的步骤。
