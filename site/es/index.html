Una caché de filas
dentro de PostgreSQL.

Lee filas por clave primaria con mget SQL o RESP. Las escrituras de PostgreSQL invalidan automáticamente las entradas de caché afectadas.

API SQL explícita · PostgreSQL 14–18 · Código abierto

Una llamada. Dos recorridos de lectura.

Un acierto elegible devuelve la fila almacenada. Un fallo o una omisión lee la tabla de origen. Tus consultas SELECT habituales conservan su recorrido existente.

psql │ lecturas por clave primaria
-- Attach your table once.
SELECT local_cache.attach_table('public.items');

-- Read rows by primary key.
SELECT local_cache.mget(
  'public.items', ARRAY[42, 7]::bigint[]
);

¿Es esta tu carga de trabajo?

¿Estás eligiendo una caché? Compara páginas de PostgreSQL, filas, vistas materializadas y Redis.

Vale la pena medir

  • Consultas repetidas de filas completas por clave primaria.
  • Un conjunto pequeño y activo de filas completas.
  • READ COMMITTED en una primaria escribible.
  • Una aplicación que pueda llamar a la API SQL explícita.

Conserva el SQL habitual

  • Uniones, rangos, agregados o resultados de consultas arbitrarias.
  • Tablas con RLS, particionadas o heredadas.
  • Una base de datos donde no puedas instalar una extensión nativa.
  • Cargas de trabajo sin un beneficio medido.

Ejecuta una demo local.

Clona el repositorio e inicia un servidor PostgreSQL desechable con filas de ejemplo. Docker compila la extensión y mantiene la demo separada de tus bases de datos.

Se requieren Git y Docker Compose
git clone https://github.com/profundium/pg_local_cache.git
cd pg_local_cache
docker compose -f examples/compose.yaml up --build --wait

Lee filas de ejemplo y comprueba los aciertos de caché. ¿Ya has clonado el repositorio? Ejecuta el último comando desde su raíz. Para un servidor existente, usa la guía de instalación.

La instalación en un servidor existente requiere reiniciar PostgreSQL.

Antes de probarlo

¿Esto reemplaza shared_buffers?

No. PostgreSQL almacena en caché las páginas de la base de datos. Esta extensión almacena por separado filas completas serializadas por clave primaria. Consulta la comparación de recorridos de lectura.

¿Almacena en caché las consultas SELECT habituales?

No. Solo las llamadas explícitas a local_cache.mget usan la caché SQL. Tus consultas existentes conservan el recorrido de ejecución normal de PostgreSQL.

¿Reemplaza a Redis?

No. El endpoint RESP2 opcional es limitado. No ofrece un conjunto general de comandos de Redis, TTL, pub/sub ni coordinación distribuida. Compara los recorridos de caché aparte de PostgreSQL y Redis.

¿Cómo compruebo las actualizaciones y el rollback?

La guía de invalidación incluye una prueba con dos sesiones. El ejemplo ejecutable comprueba escrituras no confirmadas, lectura de los propios cambios, rollback y actualizaciones confirmadas.
